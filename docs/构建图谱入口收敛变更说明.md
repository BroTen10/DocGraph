# 构建图谱入口收敛 · 变更说明

> 日期：2026-07-30
> 范围：前端（规则管理页 / 知识图谱页 / 类型定义）+ 后端（图谱路由）
> 目标：消除「构建图谱」双入口冗余，让构建动作唯一归属知识图谱页。

## 背景与问题

系统原本在 **规则管理页** 和 **知识图谱页** 各有一个「构建图谱」按钮，且底层实现不一致：

- 规则管理页：`POST /api/rules/build-graph`（**同步**，HTTP 阻塞，规则量大时会 504 超时）
- 知识图谱页：`POST /api/rules/build-graph-async`（**异步**，后台线程 + 进度轮询）

经核对，两个端点底层都调用 `graph_builder_service.build_graph`，**产出数据无差异**；差异只在调用方式与交互。重复入口 = 代码冗余 + 体验割裂 + 维护时易漏改。

## 变更一：统一到异步（上一轮）

- `frontend/src/pages/RulesPage.tsx`：`handleBuild` 由同步 `graphApi.build` 改为 `graphApi.buildAsync` + 1.5s 轮询 `getBuildStatus`（与图谱页协议对齐）。
- `frontend/src/api/client.ts`：删除同步 `graphApi.build` 封装及独占类型 `GraphBuildResponse` 的 import。
- `backend/app/routers/graph.py`：同步端点加 `deprecated` 注释，声明前端不再走同步。

效果：两页按钮行为一致，但仍是「两个平级入口」。

## 变更二：方案 B —— 删除规则页重复入口（本轮）

设计结论：构建图谱是「规则 → 图谱」的边界动作，应只有图谱页一个 owner；规则页只负责编辑 + 引导交接。

- `frontend/src/pages/RulesPage.tsx`：
  - 删除 `handleBuild` 函数、`building` 状态、`pollTimerRef` 及卸载清理 effect。
  - 移除不再使用的 `graphApi`、`ThunderboltOutlined` 导入，改引入 `useNavigate`、`ArrowRightOutlined`。
  - 工具栏原「构建图谱」按钮 → 「前往构建图谱 ↗」导航按钮（`navigate('/graph')`），仅导流、不构建。
  - `PageHeader` 下方新增 `Alert`：「本页不再内置构建入口，构建统一由知识图谱页发起」。

## 变更三：删除废弃的同步端点（本轮）

依赖核查：同步 `/build-graph` 除自身定义外，前端/脚本已无任何调用（PRD、验收报告仅为文档性提及，非功能依赖）；`GraphBuildResponse` schema 仍被 `graph_builder_service.build_graph` 用作返回类型，保留。

- `backend/app/routers/graph.py`：
  - 删除 `POST /api/rules/build-graph` 同步端点及其 `deprecated` 注释。
  - 从 `from ..schemas.graph import (...)` 移除已不再使用的 `GraphBuildResponse`。
- `frontend/src/types.ts`：删除已成孤儿的前端 `GraphBuildResponse` 接口（无人引用）。

## 涉及文件

| 文件 | 改动 |
|---|---|
| `frontend/src/pages/RulesPage.tsx` | 删除同步构建逻辑，按钮改为跳转，加提示条 |
| `frontend/src/api/client.ts` | 删除同步 `build` 封装（上一轮） |
| `frontend/src/types.ts` | 删除孤儿类型 `GraphBuildResponse` |
| `backend/app/routers/graph.py` | 删除同步端点 + 清理 import |

**未改动**：`GraphPage.tsx`（构建入口唯一 owner）、`graph_builder_service.py`、异步端点 `/build-graph-async` 与进度接口、`graph_build_progress.py`。

## 验证

- 后端：`py_compile backend/app/routers/graph.py` → 通过
- 前端：`tsc -b` → 退出码 0，类型零错误
- 全局 grep：`handleBuild` 无残留；`build-graph`（同步）无代码引用；`buildAsync` / `getBuildStatus` 仅图谱页使用

## 现状

前端「构建图谱」**唯一入口 = 知识图谱页**。规则页只做规则编辑，并通过导航按钮 + 提示条引导用户前往图谱页构建。用户旅程清爽：规则管理 →（跳转）→ 知识图谱（构建/确认）→ 文档审查。
